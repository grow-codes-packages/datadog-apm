# AGENTS.md — Grow Codes SDK for Datadog APM (`datadog-apm`)

Instructions for AI coding agents and humans working in this repository. `CLAUDE.md` is a symlink to
this file. Service-specific notes (vendor quirks, API coverage, emulator limits) live in
`docs/compatibility.md`, the README "Function overview" and `skills/datadog-apm-sdk/SKILL.md`.

## What this repository is

One API for Datadog APM in five languages, generated from
[sdk-kit](https://github.com/grow-codes-packages/sdk-kit) (version in `.sdk-kit.json`) and
completed with service code. Categories: **tracing**. The contract for every package is the
sdk-kit specification (`SPEC.md` in sdk-kit): names, defaults, error codes, environment variables,
category interfaces and the Docker contract.

## Generated files rule

- A file whose first lines contain `Generated by sdk-kit <version> — do not edit` belongs to sdk-kit.
  **Do not edit it here.** Change sdk-kit (template), release it, then run `sdk-kit sync` in this
  repository. A local edit is detected (`.sdk-kit.json` keeps a SHA-256 per file) and blocks the
  next sync until it is reverted or forced.
- To take over a generated file for good, delete its header line; sync then leaves it alone.
- Never edit `conformance/` or `.sdk-kit.json` by hand.
- `sdk-kit check` (run in CI) verifies that the required files, badges and workflows are present.

## API parity rule

The five packages expose the **same** functions, options, defaults, error codes and behaviour. Any
change to the public API lands in all five languages in the same pull request, with unit tests in
each and an integration call in the Docker suite. Names follow each language's convention:

| | TypeScript | Rust | Go | Python | Java |
| - | - | - | - | - | - |
| Methods | `camelCase` | `snake_case` | `PascalCase`, `ctx` first | `snake_case` | `camelCase` |
| Errors | `DatadogApmError` + subclasses | `Error` enum, `code()` | `*Error`, `errors.Is(err, datadogapm.ErrNotFound)` | `DatadogApmError` + subclasses | `DatadogApmException` + subclasses |
| Durations | `…Ms` numbers | `Duration` | `time.Duration` | seconds (`…_s`) / `timedelta` | `Duration` |
| Async | `Promise` + `AbortSignal` | `async` + `blocking` feature | sync with `ctx` | sync + `AsyncDatadogApmClient` | sync + `…Async` |

If one language truly cannot support something, document it in `docs/compatibility.md`.

## Tests and coverage

- Unit tests run against local mock HTTP servers; they never need network access or Docker.
- **Coverage gates** (CI-enforced, first-party code only): TypeScript, Python and Java ≥ 90 % lines
  **and** ≥ 90 % branches; Rust ≥ 90 % lines and ≥ 90 % regions; Go ≥ 90 % statements.
- Unit conformance tests are named after the ids in `conformance/core-unit.md`.
- Test fakes for users of the package ship in the testing module (TypeScript
  `@grow-codes/datadog-apm/testing`, Rust feature `testing`, Go `testkit`, Python
  `grow_datadog_apm.testing`, Java `codes.grow.packages.datadogapm.testing`).

## Docker integration rules

- `docker/compose.yml` (with `docker/compose.service.yml`) runs the real Datadog Agent
  `datadog/agent:7.85.4` forwarding to `datadog/fakeintake:v79`, the test-only `trace-reader`
  sidecar, and a one-shot `bootstrap` service that writes `/bootstrap/env`. Tests read that file
  and `GROW_DATADOG_APM_URL`.
- Each language has a `test-<lang>` service (profile `<lang>`). Its Dockerfile packs the package and
  installs it into the consumer project in `<lang>/integration/`, which runs the integration tests
  and the conformance runner.
- Always run through `make test-docker`: it uses a unique Compose project per run, publishes no host
  ports and always runs `docker compose down -v`, even on failure or Ctrl-C.
- Every public function is called at least once against the real service with a round-trip
  assertion. Functions the service cannot serve are listed in `docs/compatibility.md` and covered by
  unit tests.

## Release rules

- Releases are made by [release-please](https://github.com/googleapis/release-please) from
  Conventional Commits on `main` (`feat:`, `fix:`, `feat!:`). Never bump versions or edit
  `CHANGELOG.md` by hand. Use the language as the scope when a change touches one package.
- One release pull request covers all five packages. Tags: `typescript-vX.Y.Z`, `rust-vX.Y.Z`,
  `go/vX.Y.Z` (the Go module lives in `go/`, so its tag must be `go/v…` for `go get` to work),
  `python-vX.Y.Z`, `java-vX.Y.Z`.
- The release workflow publishes to npm, crates.io, PyPI and Maven Central; Go is published by its
  tag. Publishing credentials live only in the release environment of the GitHub repository.

## Datadog APM specifics

- **Binding decisions** (keep all five languages on them):
  - `url` = the Agent trace intake `:8126` (`/info` serves `health`, `ping`, `serverVersion`,
    `agentInfo`); the OTLP endpoint is separate (`otlpEndpoint`, default Agent host `:4318` HTTP /
    `:4317` gRPC). Env: `GROW_DATADOG_APM_*` > `DD_TRACE_AGENT_URL` / `DD_AGENT_HOST` +
    `DD_TRACE_AGENT_PORT`, `DD_SERVICE` (`OTEL_SERVICE_NAME`), `DD_ENV`, `DD_VERSION`, `DD_TAGS`,
    `DD_API_KEY`, `DD_APP_KEY` / `DD_APPLICATION_KEY`, `DD_SITE`, `OTEL_EXPORTER_OTLP_*`.
  - `recordException` / `setError` also set `error.type`, `error.message`, `error.stack`. Names:
    TypeScript/Python/Rust crate root `recordException`/`setError` (Rust also
    `record_datadog_exception`/`set_datadog_error`), Go `RecordDatadogException`/`SetDatadogError`,
    Java `DatadogSpanErrors.*`. Spans exported through `initTracing` get the attributes from the
    exception event in every language.
  - `datadogLogFields()` uses the ddtrace format (`dd.trace_id` 32 hex for 128-bit, decimal for
    64-bit; `dd.span_id` decimal); `setDatadogLogDefaults` is public in all five.
  - Propagators default `datadog, tracecontext, baggage`; `orderPropagators` puts `tracecontext`
    first so Datadog wins; a differing W3C context becomes a `terminated_context` link; same trace
    id → W3C parent wins.
  - `environment` sets `deployment.environment.name` **and** the legacy `deployment.environment`.
  - `getTrace` = spans search by default (indexed spans only); `preview: true` = trace-by-id API.
    `waitForTrace` polls every 2 s. `getDependencies` → `UNSUPPORTED`.
  - A Datadog span whose own `span_id` is missing or `0` → `VALIDATION` when mapped.
  - Any call on a closed `DatadogApmClient` / `DatadogSpansQuery` → `CANCELLED` ("client is
    closed"). TypeScript guards in service code because the generated transport says `CONFIG`.
  - Rust/Python/Java: a `TracingConfig` field equal to its template default counts as unset
    (protocol → configured protocol, propagators → Datadog list).
  - `traceSearchQueryString`: tags sorted by key, empty values and zero durations left out.
- **Service modules** (service code): TypeScript `src/{client,config,sites,ids,json,mapping,
  propagator,correlation,setup,span-errors,spans}.ts`; Rust `src/{client,config,sites,ids,mapping,
  propagator,correlation,setup,span_errors,spans,time,blocking}.rs`; Go `{client,config,sites,ids,
  mapping,propagator,correlation,setup,span_errors,spans}.go`; Python `src/grow_datadog_apm/{client,
  config,sites,ids,mapping,propagator,correlation,setup,span_errors,spans}.py`; Java
  `codes.grow.packages.datadogapm.{DatadogApmClient,DatadogApmConfig,DatadogTracing,DatadogPropagator,
  DatadogIds,DatadogLogCorrelation,DatadogSpanErrors,DatadogSpanExporter,DatadogMapping,
  DatadogSpansQuery,…}`.
- **Wire traps**: ids and nanosecond times exceed 2^53 (parse losslessly); the Agent keeps a 128-bit
  OTLP trace id only in meta `otel.trace_id` (`trace_id` = low 64 bits, no `_dd.p.tid`); a missing
  `service.name` becomes `otlpresourcenoservicename`; Datadog's trace-by-id path reads all-digit
  ids as decimal (`traceIdForPath`); the Spans API sees only indexed spans after a delay.
- **Docker**: the Agent has every intake URL pointed at fakeintake and `DD_SITE` set to a `.invalid`
  name, so nothing reaches Datadog; keys are placeholders. fakeintake cannot decode
  `/api/v0.2/traces`, so tests read the converted spans from `trace-reader`
  (`GET http://trace-reader:8080/spans?trace_id=<hex>`). Visibility latency ≈ 4–5 s after
  `forceFlush`; poll, never sleep.
- **Not testable in Docker**: the whole `DatadogSpansQuery` (Datadog SaaS API). Unit tests use the
  `*.docs_example.json` fixtures. Details: `docs/compatibility.md`.
- **Live checks** (service-owned): `live/live_test.py` (Python, package from `./python`) sends a
  trace through a real Agent and reads it back through the Spans API; `make -C live live` locally
  (starts a `datadog/agent` container), `.github/workflows/live.yml` weekly + on dispatch (Agent
  as a job service). Org secrets `DATADOG_API_KEY`, `DATADOG_APP_KEY`, variable `DATADOG_SITE`;
  without the keys it skips green. See `docs/compatibility.md` "Live checks".

## Rules for agents

- Keep secrets out of code, tests, fixtures, logs and commit messages. Credentials are always wrapped
  in the redacting secret type; error messages pass through redaction.
- Runtime dependencies must use a licence from the allowlist: Apache-2.0, MIT, BSD-2-Clause,
  BSD-3-Clause, ISC, Zlib, Unicode-3.0, Unicode-DFS-2016, 0BSD, CC0-1.0, MPL-2.0. Never GPL, LGPL,
  AGPL, SSPL, BUSL or EPL at runtime.
- Keep dependencies small; prefer the standard library.
- Before you push: `make lint coverage` for every language you touched (or all of them for shared
  changes), and `make test-docker LANGS="<lang>"` when behaviour against the service changed.
- Update the README function overview, `docs/` and the skill file when the public API changes.
